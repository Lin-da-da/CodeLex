## 1. 隔离策略（网页版零改动）

```
C:/IdeaProjects/english/
├── app/  src/  data/  package.json      ← 【只读】一行不改、不新增 script
├── docs/miniprogram/                    ← 旧方案（微信小程序），仅存档
├── docs/xhs-minitool/                   ← 本文档
├── scripts/export-xhs-data.mjs          ← 【新增】只读 data/，写 xhs-minitool/src/data/
└── xhs-minitool/                        ← 【新增】独立前端工程（自带 package.json）
    ├── index.html                        （唯一入口）
    ├── package.json / vite.config.ts / tsconfig.json
    ├── src/
    │   ├── main.ts  router.ts
    │   ├── core/        ← 从 src/lib/* 移植的纯逻辑（复制，不 import 原目录）
    │   ├── data/        ← 导出脚本生成物（gitignore）
    │   ├── pages/ components/ styles/
    │   └── native/      ← window.xhs.miniTool 封装 + 降级
    └── dist/            → zip 上传
```

**为什么独立 `package.json`**：不往根 `package.json` 加任何 script，从物理上保证 `npm run build/start`（网页版）行为零变化；小程序构建在其子目录内自成一套。

**构建不会互相污染**：Next.js 只编译 `app/`+`src/`，永远看不到 `xhs-minitool/`；Vite 只编译 `xhs-minitool/`。两条链路无共享依赖、无共享 tsconfig。

## 2. 技术选型

| 维度 | 选择 | 理由 |
|---|---|---|
| 框架 | **Preact 10 + hooks**（不用 Next/React 18） | 4KB、无 `queueMicrotask`/`MessageChannel` 强依赖，Chrome 61 稳；React 18 并发运行时对老 WebView 风险高 |
| 语言 | TypeScript（`target: ES2017`） | 逻辑层可从 `src/lib` 近乎直译复制 |
| 构建 | **Vite + `@vitejs/plugin-preact`**，`build.target: 'es2017'`，Rollup `format: 'iife'`、`inlineDynamicImports: true` | 产出**经典脚本**（非 ESM），避免 `file://`/沙箱下 `type="module"` 的 CORS 风险 |
| 路由 | 自研 **hash 路由**（`#/daily`） | 单入口、无 `history.pushState` 风险、返回键天然可用、刷新不 404 |
| 样式 | **手写 CSS**（CSS 变量 + 少量原子类），不用 Tailwind | Tailwind 的 `gap-*` 依赖 flex gap（Chrome 84+），在 61 上整套布局会塌；手写可控且体积小 |
| 状态 | 极简发布订阅 store（同旧方案 §7） | 无依赖 |
| 存储 | `localStorage`（偏好/小数据）+ `IndexedDB`（SRS/收藏/错题等大集合） | localStorage 单 origin 约 5MB，SRS 全量可达 950KB，留足余量 |
| 图表 | Canvas 2D 手绘 | 容器完整支持；不引图表库 |
| 语音 | `speechSynthesis`（唯一可行），特性检测 + 静默降级 | 白名单不含音频文件，无法预生成 mp3 |
| 端能力 | `postNote` / `saveImageToPhotosAlbum` / `writeTempFile` | 仅此三个 |

## 3. Chrome 61 / ES2017 兼容清单（最容易翻车的一段）

### 3.1 必须转译/降级的语法

| 语法/API | 基线状态 | 处理 |
|---|---|---|
| `?.` 可选链、`??` 空值合并 | ❌ (Chrome 80) | Babel target es2017 自动降级 |
| `class fields` / `static {}` | ❌ | 同上 |
| 可选 catch 绑定 `catch {}` | ❌ (Chrome 66) | 同上 |
| `Array.prototype.flat/flatMap` | ❌ (69) | `core-js` polyfill |
| `Object.fromEntries` | ❌ (73) | polyfill |
| `Promise.allSettled` | ❌ (76) | polyfill |
| `String.prototype.matchAll` / `trimStart/End` | ❌ (73/66) | polyfill 或改写 |
| `globalThis` / `queueMicrotask` | ❌ (71) | polyfill |
| `Array.prototype.at` | ❌ (92) | 改写 `arr[arr.length-1]` |
| 动态 `import()` | ⚠️ | **禁用**（改同步 require + 静态打包） |

> `async/await`、对象展开、`Object.entries`、`Array.includes`、`String.padStart` 在 Chrome 61 均可用，无需处理。

### 3.2 必须避开的 CSS（Chrome 61 不支持）

| 禁用 | 原因 | 替代 |
|---|---|---|
| **flex/grid `gap`** | Chrome 84 / 66 | 子元素 `margin`；或 `.stack > * + * { margin-top: 8px }` |
| `aspect-ratio` | 88 | padding-top 百分比 或 固定高度 |
| `backdrop-filter` | 76 | 半透明纯色 `rgba()` |
| `clamp()/min()/max()` | 79 | 固定值 + `@media` |
| `:is()/:where()/:focus-visible` | 88/86 | 用 `:focus` + 具体选择器 |
| `inset` 简写 | 87 | `top/right/bottom/left` |
| `overscroll-behavior` | 63 | 不做 |
| `position: sticky` 在 `overflow:hidden` 父级内失效 | 老实现 | 顶栏改 `fixed` + 内容 `padding-top` |
| `env(safe-area-inset-*)` | Android 61 无 | 提供 `padding-bottom: 0` 兜底，iOS 走增强 |
| `scroll-behavior: smooth` | 61 边缘 | 直接 `scrollTop = x` |

### 3.3 真机必测项（P0，不能靠推演）

1. `<script src>` 经典脚本在容器内正常执行（预期 OK）。
2. **运行时注入本地 `<script>`** 是否被允许 → 决定数据分层方案（见 §4.3），若被拦截走退化方案。
3. `speechSynthesis` 是否可用、是否静默失败（Android WebView 常无 TTS 引擎）。
4. `localStorage` 实际配额与被清理时机（切后台/杀进程后是否还在）。
5. Canvas `toDataURL` + `writeTempFile` + `saveImageToPhotosAlbum` 全链路。
6. 320px 窄屏 + 系统大字体下布局是否溢出。

## 4. 数据管道

### 4.1 导出脚本 `scripts/export-xhs-data.mjs`

只读 `data/`，输出到 `xhs-minitool/src/data/`。**精确清单（严格对齐网页版运行时口径，禁止通配）**

```
stacks.json                              → 16 栈（按 order 排序，顺序即候选池顺序）
seed/<16 个 slug>.json                   → 7,859 词
articles.json + articles-<slug>.json     → 310 篇
  ⚠️ 只有 15 个栈有文章文件（interview 栈没有 articles-interview.json）
  ⚠️ articles-*-extra*.json（10 个）运行时未加载，不得导出
phrases 60 / oral 46 + oral-extra-b 40（按 concept 去重→78）
bq 30 / followups 45 / pronunciation 42 / writing 38 / roles 8
❌ translations-*.json（7 个，网页版未加载）
```

**输出格式**：`.js`（不是 `.json`）——因为 XHR/fetch 全禁，运行时无法读 json 文件；只能 `window.__CLX_XX = {...}` 由 `<script src>` 注入。

```js
// 产物示例（无缩进、数组化编码）
window.__CLX_STACKS = [["java","Java",658,221,"☕",1], ...];
window.__CLX_INDEX  = [["heap","java","/hiːp/","n.","堆…",0], ...];  // freq: 0=high 1=mid 2=low
window.__CLX_DICT_JAVA = [["heap","/hiːp/","n.","堆…","The runtime…","Object o=…","Most long-lived…",["jvm","memory"],2,0,"…"], ...];
```

> 编码约定：`stack` 用 `stacks` 数组下标、`frequency` 用 0/1/2、空字段省略尾项，运行时按位置解包回对象（`toWord()`）。解码函数必须与导出脚本同步改版本号（`manifest.schema`）。

### 4.2 体积（实测）

| 产物 | 体积 |
|---|---|
| `index`（7859×6 字段） | 506 KB |
| `dict/<slug>`（16 个） | 合计 4,624 KB（单栈 221–375 KB） |
| `articles`（310 篇正文） | 559 KB |
| `kit`（7 类专项） | 251 KB |
| **合计** | **≈ 5.9 MB** |

### 4.3 分层加载（首屏关键）

**L0 首屏必须（≈530KB）**：`index` + `stacks` + `manifest` → 首页、每日、测验、复习、搜索、收藏、错题、统计都能跑（这些都只用索引字段）。
**L1 按需**：`dict/<slug>`（进"背词/单词详情/栈词库"时加载该栈）。
**L2 按需**：`articles`（进文章列表时）、`kit`（进口语/训练/写作/岗位时）。

- **方案 A（推荐）**：运行时注入本地脚本
  ```js
  function loadScript(src) { /* createElement('script') + promise，同源包内路径 */ }
  await loadScript('./data/dict/java.js');
  ```
  属"包内脚本"，非 `eval`、非网络请求，理论合规；**风险**：若容器对动态注入做 CSP 拦截则失败 → 必须 P0 实测（§3.3-2）。
- **方案 B（兜底）**：全部数据用静态 `<script defer>` 一次性引入。首屏多解析 ~5MB，预计 0.6–1.2s，可能触红线 → 届时对详情做字段裁剪（见 §4.4）。
- **方案 C（降级）**：只保留 `index` 的 6 个字段做"轻详情"（无例句/代码/标签），把体积压到 ~700KB，牺牲详情丰富度。**不建议**（功能等价度下降）。

### 4.4 可选瘦身（体积/内存告急时）

1. `low` 频词省略 `exampleSentences`（长数组），只留 `exampleSentence` 单句 → 约省 0.9 MB。
2. `codeExample` 超 200 字截断 → 约省 0.4 MB。
3. 文章正文段落数组化（去掉 `contentMd` 与 `contentCn` 的重复换行） → 约省 80 KB。

### 4.5 一致性契约（与网页版对齐的硬要求）

- **候选池顺序**：`stacks` 按 `order` 升序 → 栈内按 seed 文件原顺序 → 过滤 `frequency==="high"`。顺序错 = 同日每日一词不同。
- **口述合并规则**：读取 `^oral(-.+)?\.json$`、文件名 `sort()`、`concept.toLowerCase()` 去重且**先出现者胜**（78 条）。
- **SRS**：`ease 2.5 / interval 0 / reps 0` 初始；`again=1,hard=3,good=4,easy=5`；`ease += 0.1-(5-q)*(0.08+(5-q)*0.02)`，下界 1.3，四舍五入 2 位；`due = now + interval*86400000`（**不取整到天**）。
- **搜索**：haystack = `term + defCn + tags`（**不含 defEn**，与网页版全局搜索一致）；栈内搜索含 defEn（与 `/api/stacks/[slug]/words` 一致）。这个"不一致"是网页版现状，需保持（见 PRD §10）。
- **路径/计划**：L1 300 / L2 20 / L3 50 / L4 3；计划比例 0.35/0.25/0.25/0.15，最多 60 天，词量 20/40/60。

## 5. 存储层

```ts
// core/storage.ts
const PREFIX = 'clx:';
export function get<T>(k: string, fb: T): T { try { const v = localStorage.getItem(PREFIX+k); return v == null ? fb : JSON.parse(v); } catch { return fb; } }
export function set(k: string, v: unknown) { try { localStorage.setItem(PREFIX+k, JSON.stringify(v)); } catch (e) { onQuotaExceeded(k); } }
```

| 数据 | 载体 | 预估 |
|---|---|---|
| 偏好（showEn/reduceMotion/writingShowCn） | localStorage | < 1 KB |
| 计划、路径标记、已读文章（≤500） | localStorage | < 100 KB |
| SRS（≤7859 条） | **IndexedDB**（主）/ localStorage（<3000 条时） | 300–950 KB |
| 收藏（≤2000）/ 错题（≤3000）/ 日志 | IndexedDB | 200–600 KB |

- **统一 key 前缀 `clx:`**，与网页版 `codelex:` 隔离（不同 origin 本来就隔离，前缀只为人肉排查）。
- 配额异常：捕获 `QuotaExceededError` → 清理最旧的日志 → 仍失败则提示"本地空间不足，请在设置页清理"。
- 启动时做一次 schema 迁移（`clx:schema` 版本号），为后续字段变更留口。

## 7. 端能力接入（三个 API 的正确用法）

```ts
// native/bridge.ts
const mt = () => (window as any).xhs && (window as any).xhs.miniTool;

export async function shareCard(dataUrl: string, title: string, content: string) {
  const api = mt();
  if (!api) return { ok: false, reason: 'no-sdk' };      // 浏览器预览：直接降级
  try {
    const { filePath } = await api.writeTempFile({ data: dataUrl });   // 大 base64 先落文件
    await api.postNote({ title: title.slice(0, 20), content: content.slice(0, 1000),
      mediaInfo: { image_resources: [{ url: filePath }] } });           // 注意：只传白名单字段
    return { ok: true };
  } catch (e) { return { ok: false, reason: 'fail' }; }
}

export async function saveImage(dataUrl: string) {
  const api = mt();
  if (!api) return { ok: false, reason: 'no-sdk' };
  try {
    const { filePath } = await api.writeTempFile({ data: dataUrl });
    await api.saveImageToPhotosAlbum({ filePath });
    return { ok: true };
  } catch (e) { return { ok: false, reason: 'denied' }; }
}
```

**铁律**
- 必须**用户点击**触发（`saveImageToPhotosAlbum` 首次会弹系统相册授权）。
- `title ≤ 20 字`、`content ≤ 1000 字`、图片 1–18 张；**不要传未声明字段**（Schema 校验会直接 fail）。
- `postNote` 成功 ≠ 笔记发布成功 ≠ 审核通过，只能提示"已唤起发布页"。
- `filePath` 是临时文件，即用即弃，不持久化。
- 判空 + 降级：无 SDK（浏览器预览/开发调试）时按钮隐藏或提示"请在 App 内使用"。

**用在哪（这是本作的"小红书味"）**
1. **今日一词卡片**：Canvas 画词卡（术语/音标/释义/栈）→ `postNote` 发笔记（带 1 张图 + 话题）。
2. **复习战报**：今日复习 N 词/连续 M 天 → 生成战绩图 → 发笔记。
3. **导出**：收藏/词表 → Canvas 表格图 → `saveImageToPhotosAlbum`。

## 8. 降级实现细节

### 8.1 模拟面试：AI 双模（v2.0 更新）

> 在线文档新增 `window.xhs.AI`（平台内置大模型，无需 API Key，内测需 appId 加白）。因此不再"一刀切降级"，改为**双模自动切换**。

- **检测**：`window.xhs.AI.createModel` 存在 → 走 AI 版；任一环节失败（`AI_NOT_ALLOWED` / `AI_QUOTA_EXCEEDED` / 解析失败）→ 自动切换离线题库版并 toast 告知，功能不断裂。
- **AI 版**：`createModel("deepseek-v4-flash")` + `generateText({ messages })`，system prompt 约束只输出 JSON；逐题返回 `{question_en, question_cn, evaluation{score, english_comment, technical_comment, sample_answer, followup}}`，末轮返回报告 JSON。
  - 限制：`messages ≤ 40` 条 / `≤12000` 字符；`max_output_tokens ≤ 2048`；非流式；每人每天 100 次。
  - 输出审核命中返回 `AI_CONTENT_BLOCKED` → 视为失败并降级。
  - 页面固定标注"内容由 AI 生成，仅供参考"。
- **题库版（兜底）**：按栈从 `followups.json`(45) 追问链 + `bq.json`(30) 组卷，`oral.json`(78) 提供要点；结束给"自评 + 待复习术语"，**不伪造分数**。
- 报告中的 `vocab_to_review` 自动写入错题集。

### 8.2 跟读 → 录音回听自评
- 若申请麦克风：`getUserMedia({audio})` → `MediaRecorder` 录音 → `<audio>` 回放 → 三档自评（准确/一般/再练）。
- **风险**：上传页"手机权限"无麦克风选项，若容器不放行则整个入口直接隐藏（功能降级为"看 IPA + 听发音"）。
- 默认 **v1 不做录音**（Q3），只保留听音 + 三档自评。

### 8.3 复制 → 存图
- 写作模板/句式：`[保存为图片]` 按钮 → Canvas 排版 → 存相册。
- 不做"复制成功"假提示（剪贴板确实不可用）。

### 8.4 导出 → 图片
- 词表/收藏/岗位术语：Canvas 表格（分页，每图 ≤ 30 行）→ 存相册或多图 `postNote`（≤18 张）。

## 9. 性能

| 手段 | 做法 |
|---|---|
| 首屏 | **全量静态引入**：22 个数据脚本随 `index.html` 同步声明（实测 V8 解析 4.43 MiB 仅 1.4ms），`window.__CLX_*` 在 app.js 执行前全部就绪，**页面无任何 loading 态** |
| 搜索 | 预建小写 haystack（启动时对 7859 条做一次 `toLowerCase` 拼串，约 30ms）；输入防抖 120ms；结果分页 20 |
| 词条反查 | `findTerm` 用 `Map<string, number>` 倒排索引（首次 O(n) 构建），文章页逐词点击、岗位包导出从 O(7859) 降为 O(1) |
| 长列表 | 词表 200 条/批，"加载更多"；`<div>` 虚拟化不必上（Chrome 61 无 `IntersectionObserver`? 有，51+ 可用）→ 可用 IO 触发加载 |
| 渲染 | 翻卡只改 `flipped` 字段；避免整表 diff；`key` 稳定 |
| 内存 | 全部数据常驻（4.43 MiB 文本，对象化后约数十 MB），中低端机型可接受；不再做 LRU 淘汰 |
| 启动 | `manifest` 版本号校验；`data.dataReady()` 自检，缺失时 `console.warn` 指明排查方向；非关键计算延后 |

## 14. 审核驳回整改记录（v1.0.0 → v1.1.0）

### 14.1 驳回理由

> 小工具功能缺陷，可能是页面按钮无法点击

### 14.2 根因定位（按可能性排序）

| # | 根因 | 机理 | 影响面 |
|---|---|---|---|
| 1 | **L1 数据走运行时动态注入 `<script>`** | 容器沙箱/CSP 可能拦截 `document.createElement("script")` + `appendChild`；一旦拦截，`loadDict/loadArticles/loadKit` 的 Promise 永不 resolve | 词详情、背词、口语中心、听说训练、发音、写作、岗位、文章、模拟面试——**9 个页面永久停在"加载中…"** |
| 2 | **加载态页面没有退出路径** | 这些"加载中"态只渲染 `<div class="boot">加载…</div>`，**无 topbar 返回键、无 tabBar**；系统返回在部分容器里也不可靠 | 用户被困死在空白页，主观感受就是"按钮点了没反应" |
| 3 | **`window.confirm` 被容器禁用/静默忽略** | 错题集"清空"、设置页"清空全部学习数据"两处点击后无任何反馈 | 2 个按钮看起来完全失效 |
| 4 | **"开始面试"按钮依赖 `ready` 状态** | `ready` 来自 `loadKit()`，注入失败时永远 `false` → 按钮永久 `disabled` | 模面入口不可用 |
| 5 | `findTerm` O(7859) 线性扫 | 文章页逐词点击时低端机型卡顿 | 体验问题（非驳回主因） |

### 14.3 整改措施

| 措施 | 落点 |
|---|---|
| **全量静态引入**：22 个数据脚本全部写在 `index.html`，位于 `index.js` 之后、`app.js` 之前 | `index.html` |
| **postbuild 硬校验**：`dist/data` 与 html 引用必须一一对应，且 app.js 必须排在最后一个数据脚本之后，否则 `exit(1)` | `scripts/postbuild.mjs` |
| **`Loading` 组件**：整页加载态必带可点返回键 + tabBar | `src/components/ui.tsx` |
| **`Confirm` 组件**：页内确认弹层替代 `window.confirm`，带"取消/确定"双按钮 | `src/components/ui.tsx`、`src/pages/manage.tsx` |
| **`Sheet` 显式关闭按钮**：弹层不再只能靠遮罩或系统返回退出 | `src/components/ui.tsx`、`src/style.css` |
| **`WordPage` 降级**：词条缺失时渲染"词条不存在"提示页（带返回），而非永久空白 | `src/pages/learn.tsx` |
| **同步就绪判定**：`kitReady()/articlesReady()` 供页面初始化 state，消除首帧禁用闪烁 | `src/core/data.ts` |
| **`findTerm` 倒排索引** | `src/core/data.ts` |
| **启动自检**：`data.dataReady()` 为 false 时 `console.warn` 指明排查方向 | `src/main.tsx` |
| **构建链加 `tsc --noEmit`** | `package.json` |
| **新增点击全遍历测试** | `scripts/interact.mjs` |

## 15. 二次驳回整改记录（v1.1.0 → v1.2.0）

### 15.1 驳回理由

> **同一句**：小工具功能缺陷，可能是页面按钮无法点击

### 15.2 为什么 v1.1.0 没治好

v1.1.0 修的是「数据注入」和「加载态死胡同」，但**漏了整个导航层**。排查后发现全站导航几乎都是 `<a href="#/...">`：

| 位置 | 数量 |
|---|---|
| 底部 tabBar（5 个一级入口） | 5 |
| 首页入口磁贴 / 技术栈磁贴 / 往期 chip | 24 |
| 口语页 / 我的页列表项 | 12 |
| 词库列表 / 全量词表 / 搜索结果 / 文章列表 | 大量 |
| 收藏、计划、路径、面试报告、听说训练等页内跳转 | 10+ |

小工具容器普遍在**原生层拦截 URL 跳转**（Android `shouldOverrideUrlLoading` / iOS `onNavigationRequest`），点击 `<a>` 后浏览器什么都不做。此时：

- `<button onClick>` 仍然可用 → 表单提交、翻卡、评分、清空等"能点"
- **所有 `<a href="#/...">` 全部失效** → tabBar 切不了页、入口磁贴进不去、列表项点不开

审核方看到的就是「页面按钮无法点击」。而 jsdom 测试里 `dispatchEvent` 直接派发事件、绕过浏览器导航机制，所以上一轮 812 次点击全过，**完全没暴露这个问题**——这是测试盲区，不是代码没改。

### 15.3 整改措施

| 措施 | 落点 |
|---|---|
| **导航全面去 `<a>` 化**：新增 `Link` 组件（`<button type="button">` + `router.navigate()`），替换全部 20+ 处 `h("a", {href})` 与 tabBar | `src/components/ui.tsx` + 9 个页面 |
| **CSS reset**：`button.link` 抹掉 button 默认外观，使 `.tile/.item/.chip/.btn` 既有样式完全沿用；`.grid2/.grid3` 选择器补 `> button` | `src/style.css` |
| **hash 轮询兜底**：`router.start()` 增加 150ms 字符串比对，个别容器不派发 `hashchange` 时界面仍能刷新 | `src/router.ts` |
| **全局点击委托**：`bindLinkFallback()` 拦截任何残留 `a[href^="#"]`，`preventDefault` + 手动导航 | `src/router.ts`、`src/main.tsx` |
| **ErrorBoundary**：页面渲染抛错时降级为可操作错误页（带返回/回首页）并自动离开出错路由，**绝不白屏** | `src/app.tsx`、`src/components/ui.tsx` |
| **去掉 300ms 点击延迟**：全局 `touch-action: manipulation`（Chrome 36+） | `src/style.css` |
| **点击热区放大**：tabBar 返回键 34→40px、chip 24→28px、seg 32→38px | `src/style.css` |
| **运行诊断面板**：设置页展示版本/数据就绪/当前路由/容器注入/端能力/存储/视口/UA，供驳回时截图举证 | `src/pages/manage.tsx` |
| **回归断言**：smoke 新增「24 路由无 `a[href^='#']`」「tabBar 渲染为 button」「全局无 `a[href^='#']`」；interact 新增「点击 tabBar → hash 与页面必须切换」 | `scripts/smoke.mjs`、`scripts/interact.mjs` |
