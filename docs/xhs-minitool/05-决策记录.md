## 追加决策（实施中新产生）

| # | 事项 | 决策 | 理由 |
|---|---|---|---|
| D1 | AI 模拟面试 | **双模**：检测到 `window.xhs.AI` 且未返回 `AI_NOT_ALLOWED` 走 AI 版，否则自动回落离线题库版 | 在线文档新增 `window.xhs.AI` 能力（内测需 appId 加白），保留 AI 可提升「创意与场景价值」得分，同时规避未加白时功能缺失 |
| D2 | 数据编码 | 词条索引 8 字段数组 + 详情按栈拆 16 个文件；`frequency` 枚举化、`tags` 拼串 | 单文件不超 2 MiB；L0 只加载索引 |
| D3 | CSS 压缩 | **关闭** `cssMinify` | esbuild 会把 `left/top/right/bottom` 合并为 `inset`（Chrome 87+），破坏 Chrome 61 基线 |
| D4 | 脚本形态 | 产出 IIFE 经典脚本，构建后改写 `index.html`（去 `type="module"`/`crossorigin`、改相对路径、app.js 排在数据脚本之后） | 容器禁止 module，且离线 zip 无目录服务 |
| D5 | 存储 | `localStorage` 为主（同步），客户端 9.46+ 时异步镜像到平台 `setStorage`，启动时回补 | 容器不保证 localStorage 持久性 |
| D6 | 打包 | 自写 Node deflate 打包（不依赖外部 zip 命令），压缩目录内容而非目录本身 | 保证 `index.html` 在 zip 根 |
| D7 | **审核整改：数据全量静态引入** | v1.0.0 被驳回（"功能缺陷，可能是页面按钮无法点击"）。根因是 L1 数据（16 个 `dict-<slug>.js` + `articles.js` + `kit.js`）走**运行时动态注入 `<script>`**，容器沙箱/CSP 一旦拦截，`loadDict` 永不 resolve → 相关页面永久停在"加载中…"且**无返回键、无 tabBar**，表现为按钮失效/功能缺失。改为 **index.html 全量静态 `<script src>`**，并在 postbuild 增加「dist/data 与 html 引用一致性」硬校验 | 实测 V8 解析 4.43 MiB 仅 1.4ms，低端 WebView 也在几十毫秒级，全量静态的首屏成本可忽略；换来的是彻底消除单点故障 |
| D8 | **审核整改：消灭死胡同与假死按钮** | ① 所有整页"加载中"态改为带可点返回键 + tabBar 的 `Loading` 组件；② `window.confirm` 全部换成页内 `Confirm` 弹层（嵌入式 WebView 常禁用/静默忽略 confirm，点击后毫无反应）；③ `Sheet` 增加显式关闭按钮；④ `WordPage` 词条缺失时降级为可返回的提示页；⑤ `findTerm` 改为 Map 倒排索引（原 O(7859) 线性扫，文章页逐词点击会卡顿） | 直接对应驳回理由"页面按钮无法点击" |
| D9 | **构建链加类型门禁** | `npm run build` 增加 `tsc --noEmit`；新增 `scripts/interact.mjs` 点击全遍历测试；`npm run verify` = smoke + interact + audit | v1.1.0 曾因漏导入 `Loading` 只在运行时炸掉，tsc 能在构建期拦住 |
| D10 | **v1.1.0 二次驳回整改：导航全面去 `<a>` 化** | 同一句驳回理由（"可能是页面按钮无法点击"）在 v1.1.0 后再次出现。v1.1.0 修的是「数据注入」和「加载态死胡同」，但漏了更大的面：**全站导航几乎都是 `<a href="#/...">`**（底部 tabBar + 20 余处入口磁贴/列表项/chip）。小工具容器普遍在**原生层拦截 URL 跳转**（`shouldOverrideUrlLoading` / `onNavigationRequest`），一旦被拦，只有 `<button onClick>` 能用，**所有链接和 tab 全部"点了没反应"**。jsdom 里 `dispatchEvent` 绕过浏览器导航，所以上一轮 812 次点击全过却没暴露问题 | 这是最符合驳回理由的根因；改为 `<button type="button">` + 显式 `router.navigate()`，导航完全走 JS |
| D11 | **路由加固与白屏兜底** | ① `router.start()` 增加 150ms hash 轮询兜底（个别容器不派发 `hashchange`）；② 全局点击委托拦截任何残留 `a[href^="#"]` 并 `preventDefault` + 手动导航；③ `app.tsx` 加 `ErrorBoundary`，页面渲染抛错时降级为可操作的错误页（带返回/回首页）并自动离开出错路由 | 白屏是最容易被判为"功能缺陷"的表现；轮询兜底保证即便 hashchange 完全不触发界面也能刷新 |
| D12 | **触摸响应与诊断** | ① 全局 `touch-action: manipulation` 去掉老 WebView 的 300ms 点击延迟；② tabBar/chip/seg 点击热区从 32-34px 提到 38-40px；③ 设置页新增「运行诊断」卡片（版本/数据就绪/当前路由/容器是否注入/端能力可用性/存储/视口/UA） | 下次若再被驳回，直接截图举证，不再盲改 |

## 遗留项（需人工确认 / 真机验证）

1. **文本合计 5.12 MiB** 触发官方审计 WARN（>5 MiB 提示线）。已确认非"嵌入数据库"误用：词条与文章就是本产品核心内容，且离线容器无法按需下载。zip 1.71 MiB，在 2 MiB 建议值内。
2. **Chrome 61 CSS / 首屏性能 / 真机触摸仍未实测**：jsdom ≠ 容器。必须在创服平台模拟器、Android 真机、iOS 真机各验一遍，重点看 5.12 MiB 数据脚本在低端 Android 8.1 上的首屏耗时。
3. ~~运行时注入本地脚本需真机验证~~ **已消除**（D7 改为全量静态引入，冒烟中新增"未发生运行时脚本注入"回归项）。
4. **`speechSynthesis`** 在 Android WebView 大概率不可用，已做降级；真机确认后决定是否保留按钮。
5. **`window.xhs.AI` 需 appId 加白**，未加白时自动走题库版（页面会提示），不影响交付。
6. 图标 `release/icon-512.png` 已生成（4.6 KB PNG），上传页第二步使用。
7. **复审仍未通过的风险**：v1.1.0 已因同一句理由被驳第二次。若 v1.2.0 仍不过，**务必要求审核方提供具体页面与操作路径的截图**，并用设置页「运行诊断」卡片截图配合举证（版本/数据就绪/容器注入/端能力），避免继续盲改。
