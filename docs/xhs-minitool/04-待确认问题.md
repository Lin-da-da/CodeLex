# 待确认问题清单（小工具路线）

> 🔴 = 阻塞（不决策无法开工）；🟡 = 可在对应里程碑前定；🟢 = 可上线后迭代

## 🔴 Q0｜是否放弃微信小程序路线，只做小红书小工具？

**背景**：参赛要求把「小程序应用」发布为**小红书小工具**（离线 H5 zip）。微信小程序需要云开发、同声传译插件、微信审核，是另一条完全不同的技术栈，且**无法**导出成小工具 zip。两条路线同时做 = 两套工程 + 两套审核。

**选项**
- A. **只做小红书小工具**（参赛唯一有效路径）⭐推荐
- B. 小程序只做小工具，微信小程序延后（本次不做）
- C. 两条都做（工作量 ×2，且功能无法一致）

**需要你答**：选哪个？若选 C，请给优先级。

## 🔴 Q1｜能不能接受 4 项降级 + 2 项移除？

**背景**：不是实现能力问题，是容器物理限制（无网络/无剪贴板/无下载/无后端）。

| 能力 | 现状 | 小工具方案 | 接受？ |
|---|---|---|---|
| AI 模拟面试 | LLM 实时出题+评分 | 题库模面（BQ30+追问45+口述78），无评分 | ☐ |
| 跟读打分 | ASR + 0–100 分 | 自评三档（或不录音） | ☐ |
| 复制模板 | 一键复制 | 存为图片 | ☐ |
| 导出 MD/CSV/Anki | 文件下载 | 存为图片 | ☐ |
| 登录/注册 | 本地账号 | 移除 | ☐ |
| 多账号隔离 | `scope` 机制 | 移除（单机单用户） | ☐ |

**为什么不能"功能一样"**：`fetch`/`XHR` 被禁 → 无法调 LLM；`navigator.clipboard`/`execCommand` 被禁 → 复制必失败；`a[download]` 被禁 → 导出必失败；无后端 → 登录无意义。

**需要你答**：逐条接受或提出替代。

## 🔴 Q2｜大赛截止时间是哪天？评审看什么？

**背景**：小工具审核 1–7 个工作日且可能驳回，笔记也要审核。若截止在 3 天内，必须砍功能先占位。

**需要你答**：截止日期 / 是否已报名 / 评审维度（完整度、创意、完成度、传播）——决定砍哪些模块。

## 🔴 Q3｜手机权限与麦克风：是否做录音？

**背景**：上传页"手机权限"只有 相册 / 设备信息 / 设备方向，**没有麦克风**。虽然 `getUserMedia({audio})` 在容器里可用，但与上传页声明不一致，且跟读打分已降级，录音只剩"回听"。

**选项**
- A. **只勾相册，不做录音**（跟读改为纯自评）⭐推荐
- B. 勾相册 + 简介说明麦克风用途，做录音回听（有审核风险）

## 🟡 Q5｜数据要不要瘦身？

**背景**：全量 5.9MB，zip 没问题，但首屏解析慢。

**选项**
- A. 不瘦身，靠 L0/L1 分层加载（首屏只载 530KB）⭐推荐

## 🟡 Q6｜文章是否 310 篇全上？

310 篇 = 559KB（压缩后约 180KB），成本不高，建议**全上**。若想控制体积可只上 high 频主题的前 150 篇，但两端内容不一致。

**推荐**：全上。

---

## 🟡 Q7｜朗读（TTS）不可用能否接受？

**背景**：白名单不含 `.mp3/.wav`，无法打包音频；只能依赖 `speechSynthesis`，而 Android WebView 常无 TTS 引擎 → 很可能"点了没声音"。这是**高概率风险**（技术文档 §12）。

**选项**
- A. 保留按钮，不可用时置灰 + 提示"当前环境不支持发音"⭐推荐（真机实测后再定）
- B. 直接去掉朗读，听力题型改为"看词选义"

**需要你答**：若实测无声，能否接受 A 的降级？还是宁可改成 B？

## 🟡 Q8｜要不要做「发笔记」玩法？

**背景**：`postNote` 是容器唯一社交能力。做「今日一词卡片 / 复习战报」→ 一键发笔记，既贴合小红书调性，也利于大赛传播；但会增加 1 个模块工作量（Canvas 绘图 + 版式）。

**选项**
- A. 做（每日词卡 + 战报两处）⭐推荐
- B. 只做"存相册"
- C. 都不做

## 🟢 Q10｜是否需要"网页版数据导入"？

无后端 + 无文件选择（仅图片/视频）→ 无法导入 JSON。若要做，只能"手动抄 key"或"扫二维码"（二维码需 Canvas 解码库，体积/兼容风险）。**建议 v1 不做**。

## 🟢 Q11｜网页版 4 个已知问题是否同步修？

见 `01` §10（`/stacks` 死链、L1 口径、streak 口径、搜索 defEn 不一致）。本次不动网页版，小程序沿用现状。

**推荐**：沿用，上线后统一修（否则两端进度/结果不一致，更难排查）。
