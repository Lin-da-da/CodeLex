## M0 · 决策与账号准备（阻塞项）

**目标**：把 `04-待确认问题清单.md` 中的 Q1/Q2/Q3/Q7 决策掉，备齐小程序运行所需的账号与环境。

任务清单：

1. **确认阻塞项**（逐条签字确认）
   - Q1 小程序主体类型（个人 / 个体工商户 / 企业）与 AppID
   - Q2 服务类目（推荐"工具 → 效率"，备选"教育 → 教育工具"）
   - Q3 后端方案（推荐微信云开发；若有已备案域名可改自建）
   - Q7 AI 面试的 LLM 供给与资质（决定 M7 是"AI 版"还是"题库版"）
2. **注册与配置（微信公众平台）**
   - [ ] 注册小程序 → 获取 AppID（云开发必须真 AppID，不能用测试号）
   - [ ] 设置服务类目
   - [ ] 开通云开发（新建环境 `codelex-prod`），配置云函数环境变量（LLM 密钥）
   - [ ] "设置 → 第三方设置 → 插件管理" 添加**微信同声传译**插件
   - [ ] 配置《用户隐私保护指引》，勾选：相册（否）、麦克风（是）、剪贴板（是）
   - [ ] 若走自建域名：配置 `request` / `uploadFile` / `downloadFile` 合法域名（须已备案）
3. **本地环境**
   - [ ] 安装微信开发者工具（稳定版最新）
   - [ ] 确认 Node 版本可跑导出脚本（本机 `node v22.22.2` 可用）

**验收标准**：拿到 AppID；能用开发者工具新建空白项目并成功开通云开发；插件添加成功。

## M1 · 工程骨架与数据管道

**目标**：产出可运行的空壳小程序 + 从 `data/` 单向导出的数据产物。

任务清单：

1. **建目录**（不触碰任何现有文件）
   - [ ] 新建 `miniprogram/`，写入 `project.config.json`（appid 先填 `TO_BE_FILLED`）、`sitemap.json`、`app.json`（按技术方案 §4.1 草案）、`app.js`、`app.wxss`
   - [ ] 新建 `styles/app-theme.wxss`（设计变量）+ `styles/atomic.wxss`
   - [ ] 新建 `pages/daily|quiz|review|speak|mine/index` 五个空 tab 页 + `assets/tab/` 占位图标
2. **数据导出脚本** `scripts/export-mp-data.mjs`
   - [ ] 读取 `data/stacks.json` → `data/stacks.js`
   - [ ] 读取 `data/seed/*.json` → `core-index.js`（精简索引）+ `words/<slug>.js`（详情）
   - [ ] 读取 `articles.json` + `articles-*.json`（**注意：与网页版运行时口径一致，只加载非 `-extra` 的文件**）→ `articles/index.js` + `articles/<slug>.js`
   - [ ] 读取 `phrases/oral/oral-extra-b/bq/followups/pronunciation/writing/roles` → `kit/*.js`
   - [ ] 压缩：去缩进、去空值、对象转数组、枚举化、slug→索引
   - [ ] 输出 `data/manifest.json`（buildTime / totalWords / perStack / sourceHash）
   - [ ] 体积红线校验失败时 `exit(1)`
3. **体积校验脚本** `scripts/check-mp-size.mjs`
4. **package.json**：**仅新增** `mp:data`、`mp:check` 两个 script（不改 `dev/build/start`）
5. **`.gitignore`**：追加 `miniprogram/data/`、`miniprogram/node_modules/`、`miniprogram/miniprogram_npm/`

**验收标准**：`npm run mp:data` 成功；`core-index` ≤ 1.2 MB；`manifest.totalWords === 7859`；`npm run build`（网页版）行为与变更前一模一样。

## M2 · 基础设施层

**目标**：把网页版纯逻辑层 1:1 移植，先于 UI 完成并通过一致性比对。

任务清单：

1. `utils/storage.js`：`get/set/remove` + 前缀 `clx:` + 异常兜底 + 分片支持
2. `utils/srs.js`：移植 `applyGrade / ensureScheduled / dueKeys / reviewKey`（**参数不得改动**）
3. `utils/daily.js`：移植日期哈希选词（UTC 对齐）
4. `utils/quiz.js`：移植抽样与干扰项生成
5. `utils/search.js`：基于 `core-index` 的检索（term + defCn + tags，不索引 defEn）+ 栈 facet
6. `utils/mistakes.js` / `favorites.js` / `history.js`（quizHistory/reviewLog/practiceLog/readArticles/interviewSessions）/ `kitProgress.js`
7. `utils/similarity.js`：归一化 + Levenshtein，阈值 85/60
8. `utils/plan.js` / `path.js`：35/25/25/15 与 L1–L4 目标值
9. `stores/`：`prefs / review / favorites / mistakes / dict`，发布订阅 + 页面生命周期解绑
10. `utils/log.js`：启动打点与错误兜底

**验收标准**：编写 `scripts/__cmp__/` 临时比对脚本，用同一组输入在 Node 中分别跑网页版 `src/lib/*` 与小程序 `utils/*`（各 20 组用例），SRS / 每日词 / 相似度输出**逐字段相等**。

## M9 · 性能与包体治理

1. 微信开发者工具"代码依赖分析"：主包 < 2 MB、每个分包 < 2 MB、总包 < 20 MB
2. `lazyCodeLoading: requiredComponents` 生效验证
3. 冷启动打点：目标 ≤ 1.2 s（红线 1.5 s）；超标的优化顺序：① 索引异步化 ② 骨架屏 ③ 减少主包组件
4. 搜索防抖 150 ms；列表分页批大小调优（20/50/200）
5. 真机内存与帧率检查（背词翻卡、文章长列表）
6. 体验评分 ≥ 85，无 Blocker

## M10 · 合规与提审发布

1. 隐私合规：`__usePrivacyCheck__: true` + `wx.onNeedPrivacyAuthorization` 弹窗；未授权时浏览不受影响
2. 内容安全：AI 输入输出检测命中率验证
3. 审核材料：功能页面路径表、测试说明、类目资质、演示录屏（3 分钟内，覆盖 P0 链路）
4. 提审前自检（红线）：主包 < 2 MB / 冷启 < 1.5 s / 无强制登录 / 无 Blocker / 无诱导分享 / 无占位符与测试数据
5. 上传 → 提交审核 → 通过后分阶段发布（10% → 100%）
6. 准备驳回预案：类目不符 → 换类目；AI 风险 → 关闭 `AI_ENABLED` 改题库版后重提

> 无法承诺一次过审；目标是把驳回风险降到最低，并预留 1–2 轮整改时间。
