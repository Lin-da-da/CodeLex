## 🔴 Q1｜小程序主体类型与 AppID 是谁的？

**背景**：微信云开发、同声传译插件、部分服务类目都依赖主体类型。个人主体与企业主体可选类目、可申请能力不同（例如 `getPhoneNumber`、支付、部分教育类目仅企业可用）。

**选项**：
- A. **个人主体**（注册最快，1 天）
- B. **个体工商户 / 企业主体**（可选类目更全，利于后续会员/支付）

**推荐**：先确认手头已有哪个。若只有个人主体 → 走 A，并把类目定在"工具 → 效率"，避开需要资质的教育类目。

**影响**：决定 Q2 类目、Q4 AI 资质、Q7 同步能力。

## 🔴 Q2｜服务类目选哪个？

**背景**：小程序类目必须与提供的服务一致，否则审核驳回。"在线教育"通常需要相应资质。

**选项**：
- A. **工具 → 效率**（个人主体可选，描述为"英语学习工具"）⭐推荐
- B. **教育 → 教育工具 / 教育信息服务**（可能需资质，企业主体更稳）
- C. **教育 → 在线教育**（大概率需要资质证明）

**推荐**：A（若主体是企业且能提供教育类资质，再考虑 B）。

**需要你确认**：小程序后台"设置 → 基本设置 → 服务类目"里，该主体实际可选哪些（以页面下拉为准）。

## 🔴 Q3｜后端用微信云开发，还是你有已备案域名？

**背景**：小程序 `wx.request` 的合法域名**必须已备案**。当前网页版域名 `codelex-word-learn.app.workbuddy.host` 无法作为小程序的服务器域名。没有后端也能做（全部数据打进包），但 AI 面试就做不了——LLM 密钥不能放客户端。

**选项**：
- A. **微信云开发**（免备案；云函数可直连外部 LLM；自带 openid 登录/DB/存储）⭐推荐
- B. **自有已备案域名 + 自建后端**（可与网页版共用 API；需服务器与运维）
- C. **纯离线零后端**（最稳，但 AI 面试降级为题库版）

**推荐**：A。若已有备案域名，A 仍可作为云函数宿主，不必二选一。

**需要你确认**：是否有已备案域名？云开发是否愿意开通（有免费额度，超出按量计费）。

## 🔴 Q4｜AI 模拟面试：LLM 从哪来？是否有生成式 AI 资质？

**背景**（重要）：网页版 AI 面试用的是 WorkBuddy Cloud SDK，**浏览器端**、且服务端按 Origin 精确匹配，只允许 `codelex-word-learn.app.workbuddy.host` 调用 —— 小程序**无法直接复用**。小程序必须由服务端代理 LLM。

**选项**：
- A. 提供自有 LLM API Key（如混元 / DeepSeek / 智谱 / 通义等），放云函数环境变量 ⭐推荐
- B. 由 WorkBuddy 提供可在服务端调用的 LLM 通道（需确认是否支持云函数/服务端调用）
- C. 不做 AI，改用**离线题库版模拟面试**（`bq.json` 30 题 + `followups.json` 45 链 + `oral.json` 78 脚本）

**追加合规提示**：面向公众提供生成式 AI 内容，微信侧会要求内容安全机制（`msgSecCheck`），且相关服务可能涉及生成式 AI 备案/登记要求。**若无法提供，建议首发版本直接用 C**，等技术/资质齐备再开 A。

**需要你确认**：LLM 渠道 + 是否具备 AI 相关资质 + 是否接受首发降级为题库版。

## 🟡 Q5｜语音（朗读 + 跟读打分）方案？

| 方案 | 说明 | 成本 |
|---|---|---|
| A. 微信同声传译插件 ⭐推荐 | 官方免费插件，提供 TTS 与 ASR；`app.json` 声明 + 后台添加插件 | 0 |
| B. 云函数调用腾讯云 ASR/TTS | 更可控，需 SecretId/Key，按量付费 | 低 |
| C. 不做语音 | 朗读按钮与跟读打分从小程序版移除 | 0 |

**推荐**：A 为主，B 为备。风险：插件需在后台成功添加（部分类目/主体可能受限），且合成音色固定。

**需要你确认**：是否接受"朗读音色由微信插件提供"（与网页版浏览器 TTS 音色不同，功能等价但听感会有差异）。

## 🟡 Q6｜词库打包策略：全量离线 还是 按需下载？

| 方案 | 首包 | 体验 | 复杂度 |
|---|---|---|---|
| A. **主包放精简索引 + 分包放详情** ⭐推荐 | 主包 ~1.5 MB | 离线可用、搜索秒开 | 中 |
| B. 全部走远程下载 + 本地缓存 | 主包 ~0.5 MB | 首次需联网，弱网体验差 | 高（依赖备案域名/CDN） |
| C. 全量打进一个分包 | 主包小 | 进学习页要下载 3.5 MB | 低 |

**推荐**：A。7,859 词的精简索引约 950 KB，可放主包；详情按栈拆分进分包。

## 🟡 Q7｜是否要做跨端数据同步？

**背景**：网页版是纯本地账号（用户名 + SHA-256，无 salt），小程序建议用 `wx.login` + openid 静默登录。两账号体系不同源。

**选项**：
- A. **v1 不做同步**（各端独立存储，功能等价；网页版数据不动）⭐推荐
- B. v1.1 用云开发数据库做同步（需统一用户体系，网页版也要改造 → **会影响网页版**，违背本阶段约束）
- C. 提供"网页版导出 JSON → 小程序导入"的一次性迁移（P2，可选）

**推荐**：A + 预留 C。任何需要改网页版账号体系的方案，本阶段一律不做。

## 🟡 Q8｜数据范围：是否纳入未使用的 extra 数据？

网页版运行时**实际未加载** `data/articles-*-extra*.json`（约 10 个文件）和 `data/translations-*.json`。

**选项**：
- A. **与网页版保持一致**（只导出运行时真正加载的 310 篇）⭐推荐
- B. 纳入 extra 文章（小程序文章更多，但两端内容不一致）

**推荐**：A（保证两端等价）。若想扩充，应在网页版先改，再同步到小程序。

## 🟡 Q9｜是否接受导航形态调整（tabBar 5 项 + 聚合页）？

网页版有 15 个功能入口（顶部导航一级 6 + 二级 9）。小程序 tabBar 最多 5 项。

方案：每日 / 测验 / 复习 / **口语（聚合：训练·口语中心·发音·写作·岗位·模面）** / **我的（聚合：收藏·错题·统计·计划·路径·设置·登录）**，功能一个不少，入口层级多一层。

**需要确认**：是否接受？或你更希望哪个功能独占一个 tab（例如把"搜索"或"文章"提到一级）？

## 🟡 Q10｜导出功能（Markdown / CSV / Anki TSV）在小程序里怎么交付？

小程序没有 Blob 下载。方案：写入本地文件 → `wx.shareFileMessage`（发给文件传输助手/好友）+ 剪贴板复制兜底。

**选项**：A. 分享文件 ⭐推荐　B. 仅剪贴板复制　C. 去掉导出功能

## 🟡 Q11｜代码放在哪个仓库？

**选项**：
- A. **同仓库 `miniprogram/` 目录**（共享 `data/` 与导出脚本，一改词库两端同步）⭐推荐
- B. 独立仓库 `codelex-miniprogram`（物理隔离更彻底，数据需拷贝/同步）

**推荐**：A。已通过"新增目录 + 独立配置 + 不改 web 构建链"保证零影响；若你仍担心，可选 B（代价是词库更新要手工同步）。

## 🟡 Q12｜是否要顺带修掉网页版的已知问题？

盘点过程中发现网页版有 3 处已知不一致（**本次不会动网页版**，仅决定小程序是否沿用）：

1. `/path` 页面"按技术栈背词"链接指向 `/stacks`，但该路由不存在 → 点击会 404
2. 学习路径 L1 文案写"被你评级过的词条"，实际统计的是"已排入 SRS 的词数"（含未评级）
3. 学习统计的"连续学习天数"只统计 SRS 复习，不含文章/训练/面试

**选项**：
- A. **小程序沿用网页版现状**（保证等价，问题后续统一修）⭐推荐
- B. 小程序按正确口径实现（两端会有差异，但小程序更准）

**推荐**：A + 把这 3 条记进待办，后续同时在两端修。

## 🟢 Q13｜时间与发布节奏

- 小程序审核通常 1–7 个工作日，驳回后需整改重提（建议预留 2–3 轮）。
- **不能承诺一次过审**，只能最大程度降低驳回风险。
- 网页版无需重新发布（本次零改动），但如果你希望两端展示同一"数据版本"，可在小程序上线后顺带发一次网页版。

**需要你确认**：是否有上线时间点要求（例如比赛/评选截止）？若有，建议优先保 P0，把 AI 面试（M7）放到下一版。
