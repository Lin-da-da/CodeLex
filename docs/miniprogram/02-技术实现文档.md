## 1. 总体架构

### 1.1 隔离策略（核心约束：不影响网页版）

```
C:/IdeaProjects/english          ← 现有仓库，网页版
├── app/  src/  data/            ← 【只读】小程序不改动任何一个文件
├── package.json                 ← 【只读】不改脚本、不改依赖
├── next.config.mjs              ← 【只读】
└── miniprogram/                 ← 【新增】小程序工程，完全独立
    ├── project.config.json
    ├── app.js / app.json / app.wxss / sitemap.json
    ├── pages/ ...               ← 主包页面
    ├── pkgLearn/ pkgRead/ pkgKit/ pkgAI/   ← 分包
    ├── components/  utils/  stores/  styles/
    ├── data/                    ← 【生成物】由脚本从 ../data 导出，不入 git
    └── cloudfunctions/          ← 云函数（如采用云开发）
scripts/
└── export-mp-data.mjs           ← 【新增】数据导出脚本（可选执行，不影响 web 构建）
docs/miniprogram/                ← 本文档所在目录
```

**保障机制**：
1. 小程序工程使用独立的 `project.config.json` / `app.json`，Next.js 永远不会编译 `miniprogram/`（不在 `app/`、`src/`、`pages/` 下，也不被任何 web 入口 import）。
2. 数据导出是**单向**的：`data/` → `miniprogram/data/`，脚本只读取不写入 `data/`。
3. 新增 `scripts/export-mp-data.mjs` 不加入 `package.json` 的 `build`/`start` 脚本链（仅提供 `npm run mp:data` 手动触发），网页版 CI 行为不变。
4. `.gitignore` 追加 `miniprogram/data/`、`miniprogram/node_modules/`、`miniprogram/miniprogram_npm/`（.gitignore 修改不影响运行时）。
5. 部署：网页版继续用 WorkBuddy sites 发布；小程序用微信开发者工具/CLI 上传。两条链路零交叉。

> 若希望物理级彻底隔离，可把 `miniprogram/` 放到独立仓库 `codelex-miniprogram`，数据改为从本仓库 `data/` 拷贝。推荐**同仓库**以便共享数据与脚本（见 Q11）。

### 1.2 运行时架构

```
┌─────────────────── 小程序（主包 < 2MB）────────────────────┐
│  tab: 每日 / 测验 / 复习 / 口语 / 我的                      │
│  + 全库精简索引 core-index.json（term/stack/音标/释义/频率） │
│  + 公共组件、store、utils                                   │
└───────────────┬───────────────────────────────────────────┘
                │  preloadRule 预下载 / 按需 loadSubpackage
   ┌────────────┼────────────┬─────────────┬─────────────┐
   ▼            ▼            ▼             ▼             ▼
pkgLearn     pkgRead      pkgKit        pkgAI        （可选）云开发
词条详情      文章正文      口语/写作/岗位  AI 面试      云函数 + 云数据库
              内联查词      发音/训练                     + 云存储
```

**数据流**：
- 静态数据（词库/文章/专项）：构建期导出为 JSON → 打进主包或分包 → 运行时 `require` → 内存 registry 缓存。
- 动态数据（学习进度）：`wx.getStorageSync/setStorageSync` → 内存 store → 页面 `setData`（只传差异字段）。
- 网络数据（AI 面试）：小程序 → 云函数 → LLM（**密钥只在云函数侧**）。

## 2. 技术选型

| 维度 | 网页版 | 小程序版 | 说明 |
|---|---|---|---|
| 框架 | Next.js 14 + React | **原生小程序**（不用 Taro/uni-app） | 理由见 §2.1 |
| 样式 | Tailwind | `app.wxss` 设计变量 + 原子 class 手写子集 | 见 §8 |
| 状态 | React Context | 自研极简 store（`stores/*.js`，发布订阅） | 见 §7 |
| 存储 | localStorage | `wx.getStorageSync` | key 见 PRD §6.2 |
| 网络 | 站内 `/api/*` | 本地索引直读（离线）；云函数（AI） | 见 §6 |
| TTS | Web Speech API | 微信同声传译插件 `WechatSI` | 见 §9.1 |
| ASR | SpeechRecognition | 同声传译插件 `speechToText` 或 `wx.getRecorderManager` + 云 ASR | 见 §9.2 |
| LLM | WorkBuddy Cloud SDK（浏览器） | **云函数代理**（SDK 受 Origin 限制且依赖 window，小程序不可用） | 见 §10 |
| 后端 | 无 / 可选 Supabase | 微信云开发（推荐）或自建备案域名 | 见 §6.1 |
| 图表 | 无（CSS 柱状图） | canvas 2D 自绘 | ~200 行，不引库 |

### 2.1 为什么不用 Taro / uni-app

1. 网页版是 Next.js + Tailwind，Taro 无法复用任何现有组件/样式，仍需重写 UI。
2. 引入跨端框架会新增编译链、增大包体、增加调试成本，且与"不影响网页版"目标无增益。
3. 小程序是单端交付，原生方案包体最小、性能最好、与云开发/插件集成最顺。
4. 代价：业务逻辑需手工移植（算法层是纯函数，移植成本低，见 §5）。

## 3. 数据管道（关键设计）

### 3.1 导出脚本

新增 `scripts/export-mp-data.mjs`（Node ESM，`node scripts/export-mp-data.mjs` 手动执行，**不挂进 web 构建链**）：

**输入（精确清单，严格对齐网页版运行时加载口径，不采用目录通配）**

```
data/stacks.json                                   → 16 栈（按 order 排序）
data/seed/{java,python,frontend,go,cpp,agent,devops,algo,db,ml,security,
           system-design,rust,backend,spring,interview}.json        → 7,859 词条
data/articles.json + data/articles-{上面 16 个 slug}.json
        ⚠️ 实测只有 15 个栈有文章文件（interview 栈无 articles-interview.json）
        ⚠️ 运行时**不加载** articles-*-extra*.json（共 10 个），不要通配！   → 310 篇
data/phrases.json(60) data/oral.json(46) data/oral-extra-b.json(40→去重后 78)
data/bq.json(30) data/followups.json(45) data/pronunciation.json(42)
data/writing.json(38) data/roles.json(8)
❌ 不导出：data/translations-*.json（7 个，网页版运行时未加载）
```

> 口述脚本必须与网页版 `loadOral()` **同规则合并**：读取所有匹配 `^oral(-.+)?\.json$` 的文件、按文件名 `sort()`、按 `concept.toLowerCase()` 去重且**先出现的胜出**（后批次不覆盖）。顺序不同会导致 UI 列表顺序与网页版不一致。

输出到 `miniprogram/data/`：

| 产物 | 内容 | 预估 |
|---|---|---|
| `stacks.js` | 16 个技术栈元数据 | ~3 KB |
| `core-index.js` | **全库精简索引**：`[term, stack, phonetic, pos, defCn, freq]` 数组形式 | ~950 KB |
| `words/<slug>.js` | 每栈完整词条详情（例句/代码/标签/难度/defEn） | 共 ~3.5 MB |
| `articles/index.js` | 文章元信息列表（标题/分类/栈/难度/license/字数） | ~120 KB |
| `articles/<slug>.js` | 文章正文（段落数组，中英对照） | 共 ~1.2 MB |
| `kit/phrases.js`、`kit/oral.js`、`kit/bq.js`、`kit/followups.js` | 口语中心 | ~220 KB |
| `kit/pronunciation.js`、`kit/writing.js`、`kit/roles.js` | 专项 | ~120 KB |

> **为什么输出 `.js` 而不是 `.json`**：小程序包内 `.json` 文件会被当作配置文件处理且无法被 `require` 为数据；`.js` 用 `module.exports = [...]` 可直接 `require`。这是微信小程序的既定约束。

### 3.2 体积压缩策略

1. **去缩进**：`JSON.stringify(x)` 无空格，约省 35–40%。
2. **去空值**：`null` / `undefined` / 空数组字段全部删除（运行时按可选字段兜底）。
3. **对象转数组**：索引行用定长数组 `[term, stackIdx, phonetic, pos, defCn, freq]` 代替对象，省掉重复 key，约再省 30%。
4. **枚举化**：`frequency: "high"|"mid"|"low"` → `0|1|2`；`stack` slug → 数字索引（配 `stacks.js` 反查）。
5. **分包切分**：`words/<slug>.js` 按栈独立，配合分包按需加载，避免一次性下载 3.5 MB。
6. **字段裁剪（可选 P2）**：详情中的 `exampleSentences` 保留全部，`codeExample` 超 400 字截断。

**预算校验**：脚本末尾打印体积表，并对以下红线 `process.exit(1)`：
- 主包产物（`stacks` + `core-index`）> 1.2 MB
- 单栈详情 > 400 KB
- 分包聚合 > 1.9 MB

### 3.3 数据一致性保障

- 脚本内做与 `scripts/validate-seed.mjs` 相同的校验（term 非空、defCn 非空、栈内 term 唯一、frequency 合法）。
- 输出 `miniprogram/data/manifest.json`：`{ buildTime, totalWords, perStack: {...}, sourceHash }`，小程序"设置-关于"页展示，用于两端对账。
- **铁律**：网页版 `data/` 变更后，必须重跑导出脚本；CI 中加一个可选 job 做哈希比对（不阻断 web 发布）。

### 4.2 分包数据加载模式

主包 JS **不能** `require` 分包内的 JS。采用"**分包自注册**"模式：

```js
// 主包 stores/dict.js
const registry = {};
export function registerDict(words) { Object.assign(registry, words); }
export function getDetail(stackIdx, term) { /* 查 registry，未命中返回 null */ }
```

```js
// pkgLearn/pages/word/index.js（分包内）
const detailData = require('../../data/words/java.js'); // 分包内相对路径，合法
getApp().globalData.dictApi.register(detailData);
```

- 进入 `pkgLearn` 任一页面时，在页面 `onLoad` 中把该栈详情注册进全局 registry（幂等）。
- 主包页面若需要详情（如每日一词展示例句），先判断 registry 是否就绪；未就绪则先 `wx.loadSubpackage({ name: 'learn' })` 再跳分包页，或用 `preloadRule` 保证已下载。
- 内存占用：单栈详情 ~250 KB，全部注册约 3.5 MB（可接受，必要时 LRU 只保留最近 3 栈）。

## 5. 核心算法与业务层移植

全部为纯函数，从 `src/lib/*` 逐行移植到 `miniprogram/utils/`，**禁止修改任何参数**。

| 网页版 | 小程序 | 移植要点 |
|---|---|---|
| `src/lib/srs.ts` | `utils/srs.js` | `applyGrade/ensureScheduled/dueKeys/reviewKey` 原样移植；`localStorage` → `storage.js` |
| `src/lib/daily.ts` | `utils/daily.js` | 日期哈希算法逐字符对齐（FNV 风格），保证两端同日同词；时区用 UTC |
| `src/lib/quiz.ts` | `utils/quiz.js` | 随机池抽样 + 干扰项生成；随机源改为 `Math.random()`（网页版同源） |
| `src/lib/wordData.ts`（检索部分） | `utils/search.js` | 基于 `core-index` 数组的线性扫描（7,859 条 < 20 ms）；haystack 预构建放内存 |
| `src/lib/mistakes.ts` / `favorites.ts` / `quizHistory.ts` / `reviewLog.ts` / `practiceLog.ts` / `readingLog.ts` / `interviewLog.ts` / `kitProgress.ts` | `utils/*.js` | 逐个移植，含各自的条数上限（200/1000/2000/3000 等） |
| `SpeakPractice` 相似度 | `utils/similarity.js` | 归一化 + Levenshtein，阈值 85/60 不变 |
| `PathClient` / `PlanClient` 规则 | `utils/path.js` / `utils/plan.js` | L1–L4 目标值、35/25/25/15 比例硬编码保持一致 |
| `interviewKit.ts` 口述去重 | `utils/kit.js` | `concept` 小写去重逻辑一致 |

### 5.1 存储层 `utils/storage.js`

```js
const PREFIX = 'clx:';
function get(key, fallback) { try { const v = wx.getStorageSync(PREFIX + key); return v === '' ? fallback : v; } catch { return fallback; } }
function set(key, value) { try { wx.setStorageSync(PREFIX + key, value); } catch (e) { /* 配额超限：触发分片或清理最旧日志 */ } }
```

### 5.2 大对象分片（风险预案）

`clx:review` 在极端情况（用户把 7,859 个词全加进复习）会逼近单 key 1 MB 上限。方案：
- `utils/reviewStore.js` 内部按 `term` 首字符分 16 片：`clx:review:0` … `clx:review:f`，每片 < 100 KB。
- 对外仍暴露 `loadReview()/saveReview()` 整体 API，内部合并/拆分，业务层无感。
- 首次读取时若检测到旧的整包 key，自动迁移到分片并删除旧 key。

### 5.3 页面 `setData` 规范

- 单次 `setData` 数据 ≤ 256 KB，禁止整表回传。
- 长列表用分页 + `wx:key`，批次 20/50 条；全量词表按 200 条一批"加载更多"。
- 卡片翻面等高频交互只 setData 变化字段（如 `setData({ flipped: true })`）。

## 6. 后端与网络方案

### 6.1 选型对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. 微信云开发** | 免备案域名；云函数可直连外部 HTTPS（不受 request 域名白名单限制）；自带登录/DB/存储；免费额度够 MVP | 计费随量增长；AI 需自备 LLM 密钥 | **推荐（默认）** |
| B. 自建后端 + 自有域名 | 完全可控，可与网页版共用一套 API | 域名必须 **ICP 备案**（当前 `*.workbuddy.host` 不可用）；需服务器运维 | 备选（若已有备案域名） |
| C. 纯前端零后端 | 包最小、最稳 | AI 面试无法实现（LLM 密钥不可下放客户端） | 仅当放弃 AI 面试时 |

> **关键事实（必须知悉）**：小程序 `wx.request` 的合法域名必须已备案。`codelex-word-learn.app.workbuddy.host` **不能**直接作为小程序服务器域名。因此 v1 若保留 AI 面试，**必须**走云开发（或备案域名）。

### 6.2 云开发资源清单

| 资源 | 用途 | 备注 |
|---|---|---|
| 云函数 `login` | `wx.login` code → openid，返回自定义态 | 静默，不弹授权 |
| 云函数 `interview` | 代理 LLM：出题/评估/追问/报告 | 密钥存云函数环境变量 |
| 云函数 `msgSecCheck` | 内容安全检测（用户答案 + 模型输出） | 调用 `openapi.security.msgSecCheck` |
| 云数据库（可选 v1.1） | 学习进度跨设备同步 | 集合：`review`、`favorites`、`mistakes` |
| 云存储（可选） | 音频/TTS 缓存、导出文件暂存 | |

### 6.3 请求层 `utils/request.js`

- 统一封装 `callFn(name, data)`：`wx.cloud.callFunction`，含超时（默认 20 s）、重试（1 次）、错误码映射。
- 云开发未初始化或调用失败 → 返回结构化错误，UI 层走降级（AI 面试降级到题库版）。
- 所有云调用入口集中在 `utils/cloud.js`，便于整体关闭（审核期开关）。

## 7. 状态管理

极简发布订阅 store（`stores/`）：

```js
// stores/review.js
const listeners = new Set();
let state = loadReview();
export function get() { return state; }
export function update(fn) { state = fn(state); saveReview(state); listeners.forEach(l => l(state)); }
export function subscribe(fn) { listeners.add(fn); return () => listeners.delete(fn); }
```

- 页面 `onLoad` 订阅、`onUnload` 取消订阅，避免内存泄漏。
- 跨页面数据一致性：写入即落 Storage + 广播；页面 `onShow` 重新拉取一次（应对后台切前台）。
- 全局偏好（showEn / writingShowCn / 减少动效）放 `stores/prefs.js`，启动时同步到 `app.globalData`。

## 9. 语音方案

### 9.1 TTS（朗读）

**主方案：微信同声传译插件（WechatSI）**
- 免费、官方，提供 `textToSpeech`，返回音频文件路径，用 `wx.createInnerAudioContext` 播放。
- `app.json` 声明 plugins；后台"插件管理"添加；首次调用有约 200 ms 延迟，做本地缓存（同文本缓存 24 h，存 `wx.env.USER_DATA_PATH`）。
- 需注意：插件有调用频率限制（官方未明示，实测单次会话足够），做串行队列 + 失败静默。

**降级方案**：
- `wx.createInnerAudioContext` + 云存储预生成音频（成本高，v1 不做）。
- 静默失败：朗读按钮置灰并提示"当前环境不支持朗读"，**绝不阻塞主流程**。

### 9.2 ASR（跟读打分）

**主方案：同声传译插件 `speechToText`**（`wx.getRecorderManager` 录音 → 插件转写）
- 语言 `en_US`（插件参数 `lang: 'en_US'`）。
- 转写文本 → `utils/similarity.js` → 分数，与网页版算法一致。
- 需要 `scope.record` 隐私授权，首次触发走 `wx.onNeedPrivacyAuthorization`。

**备选**：`RecorderManager` 录 MP3 → 云函数 → 腾讯云 ASR（需 SecretId/Key，付费）。仅在插件不可用或打分不准时启用（P2）。

### 9.3 音频资源

- 无内置音频文件（包体红线）。所有发音由插件实时合成。
- 听力辨词题型：自动播放一次 + 手动重播按钮（网页版同样只自动播放一次）。

## 10. AI 模拟面试实现

### 10.1 为什么不能直接复用网页版 SDK

`src/lib/cloud.ts` 依赖：① `window` 浏览器环境；② WorkBuddy Cloud SDK（浏览器 OAuth relay）；③ **服务端按 Origin 精确匹配**，仅 `codelex-word-learn.app.workbuddy.host` 可用。三者小程序均不满足。

### 10.2 云函数代理设计

```
小程序 → wx.cloud.callFunction('interview', { action, payload })
       → 云函数：鉴权(openid) → 频率限制 → 内容安全(输入) → LLM(HTTP) → 内容安全(输出) → 返回
```

- `action`：`start`（生成首题）/ `answer`（评估 + 追问 + 下一题）/ `report`（最终报告）。
- **非流式**（云函数不支持向小程序流式推送），UI 用 loading + 分阶段文案（"面试官正在出题…"）覆盖 3–10 s 等待。
- Prompt 从 `Interviewer.tsx` 中原样提取，存云函数侧 `prompt.js`，保证两端提问风格一致。
- 模型：需确认可用 LLM 与密钥（见 Q7）。候选：① 已备案的国内大模型（如腾讯混元/DeepSeek/智谱）；② WorkBuddy Cloud 若提供服务端 SDK 则优先复用。
- 超时：云函数 `timeout: 60s`，前端 20 s 超时重试 1 次，二次失败走降级。

### 10.3 内容安全与合规

- 用户输入（中文/英文答案）→ `msgSecCheck`（`openapi.security.msgSecCheck`）；命中风险 → 提示"内容不合规"并不入库。
- 模型输出同样检测后再展示。
- 页面固定展示"内容由 AI 生成，仅供参考"角标。
- 频率限制：单用户 30 次/天，超出提示次日再来（防刷与控成本）。

### 10.4 降级开关（`utils/feature.js`）

```js
export const AI_ENABLED = true; // 审核期置 false
```

`AI_ENABLED = false` 时，"模拟面试"入口改为**题库版**：从 `bq.json`（30 题）+ `followups.json`（45 链）+ `oral.json`（78 脚本）离线组卷，提供固定参考答案要点，无评分、无 LLM。功能入口不消失，用户体验不断裂。

## 11. 性能与包体治理

1. `lazyCodeLoading: "requiredComponents"`（按需注入），首屏只注入 tab 页代码。
2. 主包只放 5 个 tab + 聚合页 + 索引；所有二级功能进分包。
3. 图片全部走 iconfont/内联 SVG base64 或纯 emoji；禁止位图资源进包（tab 图标除外）。
4. `core-index` 在 `App.onLaunch` 中**异步**加载（`require` 后放 globalData），首屏骨架屏占位，避免阻塞启动。
5. 搜索/词表渲染做防抖（150 ms）+ 分页，长列表用 `<scroll-view>` + `onReachBottom`。
6. 启动打点：`App.onLaunch` 记录 t0，`onShow`/首屏 `onReady` 记录 t1，本地日志（可上报云开发）用于监控冷启动。
7. 每次构建用微信开发者工具"代码依赖分析"核对：主包 < 2 MB、分包 < 2 MB。

## 14. 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| LLM 密钥/备案不确定 | AI 面试无法上线 | `AI_ENABLED=false`，上题库版（功能不缺失，体验降级） |
| 同声传译插件不可用/被限制 | 朗读与跟读打分失效 | 朗读降级为"仅文本 + 提示"；跟读打分降级为"自评三档" |
| 主包超 2 MB | 无法上传 | 索引进一步裁剪（去掉 pos/phonetic → 省 ~200 KB）或索引移入分包 |
| `clx:review` 触顶 1 MB | 数据丢失 | §5.2 分片方案，默认启用 |
| 类目/资质不符被驳回 | 无法发布 | 备选类目"工具 → 效率"；剥离 AI 功能 |
| 文章 license/版权 | 内容合规 | 保留 license 展示，剔除来源不明内容 |
| 数据同步需求变更 | 架构返工 | v1 预留 `stores/sync.js` 接口，v1.1 再接云 DB |
